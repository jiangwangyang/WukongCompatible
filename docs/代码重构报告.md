# WukongCompatible 代码重构报告

> 适用范围：`src/main/java/com/p1nero/wukong/` 全部 90 个 Java 源文件（约 18100 行）。
> 本次重构共修改 46 个文件，净删除约 81 行（+350 / -431）。未改动 `src/main/resources` 任何资源。
> 项目背景说明：本项目是《黑神话:悟空》主题的 Minecraft Forge 模组（MC 1.20.1），基于 Epic Fight 20.14.17 战斗框架实现劈棍/立棍/戳棍/大圣四套棍式技能。阅读本报告无需了解项目代码。

---

## 一、项目当前情况（修改前）

项目此前已经历两轮死代码清理（见 `docs/代码清理分析报告.md`），大块死代码已清除，但仍存在四类问题：

1. **风格不统一**：约 20 个文件使用通配符 import（如 `import yesman.epicfight.skill.*;`），其余文件使用显式 import，两种风格混存；3 个文件用全限定名 `new java.util.ArrayList<>(...)` 而非 import；部分文件类注释放置在类注解之后。
2. **顺序不统一**：四个重击技能类中，`getHeavyAttacks()` 重写方法有的排在构造方法之前、有的之后；`StaffStance` 的静态工厂方法夹在构造方法与重写方法之间；两个粒子类把内部类放在构造方法之前；`WukongAnimations` 把两个静态辅助方法放在 80 个静态字段之前。
3. **残留无用代码**：全库无任何调用的死方法/死字段 8 处；`AnimationJudge.isCharging()` 中同一条件被完全重复判断了两遍；注释掉的调试日志与旧实现残留 11 处。
4. **注释问题**：3 处 TODO/FIXME 陈旧标记；若干注释与代码行错位（注释描述的是下一行的内容）；若干注释仅复述代码字面含义；1 处英文注释（规范要求中文）；3 个类与 9 个方法缺少注释。

## 二、修改后的情况与逐项变动

统一执行的约定：**成员顺序 = 静态字段 → 实例字段 → 静态块 → 静态工厂方法 → 构造方法 → 其余方法（保持原相对顺序）→ 内部类/Builder；类注释在类注解之前；import 全部显式展开；注释为中文单行且与所描述的代码对应。**

### 2.1 通配符 import 展开（20 个文件）

- **是什么**：把 `import 包.*;` 全部替换为实际使用类的显式 import，并删除与同包显式 import 的重复行。
- **为什么**：显式 import 能直接看出每个类的外部依赖，避免同名类歧义，是项目多数文件已有的风格。
- **作用**：纯声明层面整理，不改变任何运行行为。
- **出处**：`WukongSkillDataKeys`、`WukongSkills`、5 个法术技能、5 个棍式技能、`WukongAnimations`、`WukongItems`、`DaShengArmorItem`、`WKCapabilityProvider`、`BasicAttackMixin`、`CloudStepLeftEntity`、`FakeWukongEntity`、`DingParticle`、`DingEntityAfterImageParticle` 等。包内容清单来自 `libs/EpicFight-20.14.17.jar` 与 `forge-1.20.1-47.4.16_mapped_parchment_2023.09.03-1.20.1.jar`。

## 四、风险与规避

1. **物品 NBT 特效计时机制的移除**：`onPlayerTick` 每 tick 递减 `wukong_has_effect_timer` NBT，删除后该 NBT 不再更新。经全库（Java 与 resources）检索确认没有任何读取方，属只写数据，删除无功能影响；反而消除了「每 tick 写 NBT 导致服务端误判装备变化」的同类隐患（参见提交 `ad0ce50` 的修复说明）。**规避方式**：若未来需要物品特效计时，应改用 `StaffScaleState` 式的客户端缓存，不要写物品 NBT。
2. **公开方法/常量的删除**（`applyKnockback`、`CameraOperationFov`、`MAX_ANGLE_FOV` 等）：理论上影响依赖本模组的外部代码，但本项目是独立模组而非库，且已全库检索确认无调用。**规避方式**：如需回滚，单项均在 git 历史中可查。
3. **大面积 diff 的审阅成本**：46 个文件变动。所有改动均可归类为「import 展开 / 位置移动 / 删除死代码 / 注释调整 / 格式化」五种无行为变更的类型，且 `./gradlew compileJava` 编译通过。
4. **未运行游戏实测**：按项目规范仅做编译检验，未启动游戏。技能连招、粒子、渲染等运行时行为虽未被代码改动触及，仍建议提交后常规进游戏抽查劈棍/立棍/戳棍/大圣四式重击与定身、聚形散气两个法术。
