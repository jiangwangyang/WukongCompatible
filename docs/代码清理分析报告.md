# WukongCompact 冗余代码清理分析报告

> 适用范围：`src/main/java/com/p1nero/wukong/` 全部 Java 源码与 `src/main/resources` 资源。
> 状态：**清理已完成**。本文档记录两轮清理的结果：第一轮（提交 `c4e81db`）删除了报告初版列出的大部分死代码；第二轮（本次）统一复核全库后，清除了第一轮遗留项与新发现的死代码。
> 对读者的说明：本项目是一个《黑神话:悟空》主题的 Minecraft 模组，基于 Epic Fight 战斗框架实现劈棍/立棍/戳棍/大圣四套棍式技能。技能动画在 Java 代码中以"动画访问器"（`AnimationAccessor` 静态字段）声明，再通过 `nextAccessor(...)` 注册后才有实际内容；**只声明不注册的字段永远是 null，任何对它的调用都会引发空指针崩溃**。

### 1.4 与父类完全相同的空 override（9 处）

- **是什么**：5 个法术技能与 4 个 HeavyAttack 技能各自 override 了 `registerPropertiesToAnimation()`，方法体只有 `return this;`。
- **为什么删**：已反编译验证 Epic Fight 20.14.17 基类 `Skill.registerPropertiesToAnimation()` 的字节码就是 `aload_0; areturn`（即 `return this;`），`WeaponInnateSkill` 未再 override，删除后行为逐字节一致。
- **出处**：`ShenfaJuxingsanqiSkill`、`FashuAnshenfaSkill`、`ShenfaTongtoutiebiSkill`、`FashuDingshenfaSkill`、`ShenWaiShenFaSkill`、`ThrustHeavyAttack`、`SmashHeavyAttack`、`GreatSageHeavyAttack`、`PillarHeavyAttack`；基类证据来自 `libs/EpicFight-20.14.17.jar` 的 `yesman/epicfight/skill/Skill.class`（javap 验证）。

## 三、复核后确认"保留/无害"的项（避免误删）

- **`biped/*/data/` 目录下的 json**（如 `thrust/data/thrust_pre.json`、`smash/data/smash_charging.json`）：内容是刀光拖尾特效（`trail_effects`）与动画层（layer/masks）元数据，不是动画本体，代码本就不按 `data/` 路径注册动画，属正常设计，**保留**。
- **`StaffPassive`、`ThrustHeavyAttack` 中分散在不同 if 分支里的单个 `event.setCanceled(true)`**：分属雷伤免疫/棍花格挡/防摔落/退寸等不同分支，不是重复笔误，**保留**。
- **设计性空 override**（`CloudStepLeftEntity.setItemSlot` 等防复制保护、Epic Fight 生命周期钩子）、**所有 mixin 类**（被 `wukong.mixins.json` 引用）：**保留**。
- **`WukongWeaponCapabilityPresets` 的 `livingMotionModifier` 弃用 API 警告**（编译期 69 个警告的主要来源）：Epic Fight 标记待删除但仍可用的 API，替换需要逐动画验证表现，超出本轮范围，**保留**，编译警告不影响运行。

## 五、风险与规避

1. **误删风险**：已用全库文本检索交叉验证每个被删符号"零读取/零赋值"，并通过编译验证；动画访问器类资源由路径字符串驱动，删除 Java 字段不影响资源 JSON。
2. **存档兼容**：`WKPlayer.damageReduce` 从未写入 NBT（`saveNBTData` 只存 `lastSkill`），删除不影响旧存档。
3. **配置兼容**：本轮未动任何 Forge 配置项，`config/wukong-common.toml` 无需处理。
4. **命令兼容**：`/wukong` 原为空壳，无任何子命令与执行体，删除后玩家输入会提示"未知命令"，无功能损失。
5. **后续维护**：若未来要恢复"蓄力循环动画"或"衍生长循环"功能，应在 `WukongAnimations` 中重新 `nextAccessor` 注册后再引用，切勿直接引用未注册字段（这正是本轮清除的隐患模式）。
