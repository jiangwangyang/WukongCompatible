# 项目代码注释统一说明

## 一、本次做了什么

本次改动只做了一件事: 为项目的全部代码文件统一注释风格, 没有修改任何一行代码逻辑。

涉及范围:
- src/main/java/com/p1nero/wukong 下的全部 89 个 Java 文件
- tools/convert_dasheng_armor.py (1 个 Python 工具脚本)

合计 90 个文件。

## 二、为什么这么做

项目原有的注释情况参差不齐, 存在三类问题:

1. 一部分文件完全没有注释, 阅读时不知道类和方法的用途 (例如 WukongStyles.java, WukongColliders.java, 大部分 entity 和 item 类)。
2. 一部分文件使用 /** ... */ 块注释 (javadoc 形式), 与项目编码规范要求的单行注释 // 不一致。
3. 少量注释中使用了全角标点 (如全角逗号, 全角括号), 与编码规范要求的半角标点不一致; 还有少量注释是英文或存在错别字, 与项目其余注释不统一。

统一注释后, 任何一个没有读过项目代码的人都可以通过注释快速了解每个类是做什么的, 每个方法做什么事。

## 三、统一后的注释规范

本次统一严格遵循 AGENTS.md 中的编码规范, 最终所有文件达到以下标准:

| 规范项 | 统一后的标准 |
|---|---|
| 注释形式 | 只使用单行注释 // (Python 使用 #), 全项目已无任何 /* */ 或 /** */ 块注释 |
| 注释语言 | 全部简体中文, 原有英文注释已翻译为中文 |
| 标点 | 注释内一律半角 ASCII 标点, 全角标点已清零 |
| 类注释 | 每个类 (含枚举/接口/内部类) 都有注释说明用途 |
| 方法注释 | 每个方法都有注释说明功能 |
| 字段/逻辑注释 | 关键字段和复杂逻辑段落补充了说明 |
| 原有信息 | 原有 // TODO 注释, 注释掉的调试代码全部原样保留 |

## 四、修改前后的区别

修改前:
- 部分类和方法没有任何注释, 需要通读代码才能理解用途
- 注释形式混杂: /** */ 块注释与 // 单行注释并存
- 注释语言和标点不统一: 中英文混用, 全角半角混用

修改后:
- 全部 89 个 Java 文件和 1 个 Python 脚本的每个类和方法都有中文注释, 关键字段与复杂逻辑段有补充说明
- 全项目注释统一为 // (Python 为 #) 单行形式, 无块注释残留
- 注释全部为中文半角标点, 风格一致

## 五、功能点清单 (均为注释层面的变动, 不涉及任何功能)

| 变动点 | 是什么 | 为什么 | 作用 |
|---|---|---|---|
| 补全缺失注释 | 为原先无注释的约 40 个文件补上类/方法/字段注释 | 原文件无注释难以阅读 | 提升可读性, 方便维护 |
| 块注释转单行注释 | 将 /** */ 改写为等价的 // | 与编码规范统一 | 全项目注释形式一致 |
| 全角标点规范化 | 注释中的全角逗号/括号/引号等改为半角 | 与编码规范统一 | 注释风格一致 |
| 英文注释中文化 | 将少量英文注释翻译为等价中文 | 统一注释语言 | 中文读者直接可读 |
| 注释纠错 | 修正少量错别字与复制粘贴错误的注释 (如 "是否正在切手技" 误写为 "是否正在切手技" 之外的错文, 伤害减免被误标为防止坠机等) | 注释与代码实际行为不符会误导读者 | 保证注释内容准确 |

## 六、改动来源 (具体出处)

- 注释规范的依据: 项目根目录 AGENTS.md 的 "编码规范" 一节 (统一单行注释, 中文注释, 类和方法必须有注释)。
- 改动涉及的代码: src/main/java/com/p1nero/wukong 下的 89 个 Java 文件 (capability, client, effects, entity, epicfight, item, listener, mixin, network, Config, WukongMoveset) 以及 tools/convert_dasheng_armor.py。

## 七、风险评估与规避方式

| 风险 | 说明 | 规避方式 | 实际验证结果 |
|---|---|---|---|
| 误改代码逻辑 | 批量修改注释时可能误删或改动代码行 | 逐文件修改后用 grep 全量复查, 确认除注释外无任何改动 | 已复查, 无代码行变动 |
| 编译失败 | 修改可能导致语法错误 | 已执行编译检验 (gradlew compileJava) | 编译通过 (exit 0) |
| 遗留警告 | 编译输出有 69 个警告 | 逐条核对 | 全部为 epicfight 依赖库 API 的弃用 (deprecation) 警告, 属项目原有情况, 与本次注释改动无关, 修改前后完全一致 |

## 八、是否有遗漏

- 已覆盖: src 下全部 89 个 Java 文件, tools 下 1 个 Python 脚本。
- 不涉及: 资源文件 (.json/.ogg/.toml 等) 和 build 目录不属于代码, 无需注释。
- 两处含义不完全明确的命名已在注释中如实按代码行为描述, 未臆测业务含义:
  - WukongMoveCoordFunctions 中的 SJZT 标志 (注释为 "一次性视角俯仰角调整标志")
  - JinGuBangRenderer 中的 MAX_CZLT (注释按实际行为描述: 贴图档位索引随发光动画循环递增)

如你了解这两个命名的准确业务含义, 可以告诉我, 我会把注释更新为更准确的描述。
